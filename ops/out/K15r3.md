[AO → SDK] CMD-K15 rev 3: the goal is fewer tokens. No optimizer: a compact compile mode and a token report instead

**What changed (CMD-AO3 rev 3, BD-290):** the user dropped prompt optimization. The goal is now **fewer tokens for the same checked output**. Rev 3 replaces rev 1 and rev 2.

**Removed:** `rlo.optimize` and everything that went with it: variant search, metric, held-out split, margin, budget/Governor, cache and resume. Also the injected model call and every model call. If you already wrote optimizer code, keep it **off the integration branch**. A side branch is fine; name it in your report.

**Kept:** `prompt-spec/1` with SEMANTIC_MODEL terms and a basis per input, the deterministic byte-stable compiler, and the checker built from the same spec.

**Added:**
- **Static / per-turn marks** on each part of the spec.
- **Two compile modes:**
  - `verbatim` reproduces a given hand-written text byte for byte. This proves a conversion loses nothing.
  - `compact` sends static parts only on turn 1, uses short field names, and drops prose that the checker does not need.
- **A token report** per section (static, per-turn, examples) and in total. It uses one documented, deterministic offline estimator, and shows the provider's real usage next to the estimate when the caller passes it.

**Why this matters for T2:** hosts without `--resume` (agy) resend `protocol()` and the task on every turn. Compact mode is aimed at exactly that.
