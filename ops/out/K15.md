[AO → SDK] CMD-K15: prompt-spec/1, a deterministic compiler and checker, and rlo.optimize (POL-2 T1)

**Why now:** the user asked baseline to add prompt optimization, and then to convert prompts automatically from the semantic model. Baseline made that POL-2 ([CMD-AO3](https://github.com/cogito5170/baseline/issues/18#issuecomment-5980267119), BD-288). Today our prompts are hand-written `str.format` text with no spec, no metric and no search. T1 is the rlo-sdk base. T2 (GA moves the `ga gemini` plan prompt onto it) is issued only after baseline judges T1 a success.

**Shape:**
- `prompt-spec/1` is data, not code. Inputs carry SEMANTIC_MODEL terms and a basis. The LLM answer is an **Opinion** (SEMANTIC_MODEL section 1), never State.
- One spec builds both the prompt text and the answer checker, so they cannot drift.
- `rlo.optimize` is a search with a deterministic metric, a held-out split and a margin. Spend is capped through the Governor; repeat calls are cached and the run resumes after a restart. It returns a result and never deploys a prompt by itself. A changed prompt reaches the products only as a code diff with a baseline verdict.

**Limits (POL-2 S5):**
- T1 spends **0 Gemini requests**. The model is an injected function, and every test uses a fake.
- rlo-sdk does not import a provider SDK and does not read keys.
- No keys or tokens in the repo, the issue or messages.
- Any budget above the free tier is a HUMAN_QUEUE item for baseline, not a session decision.

If something in the scope is unclear, ask on this issue. A choice that changes POL-2 itself goes to baseline.
